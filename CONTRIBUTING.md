## Report a bug

Open an issue that says what you did, what you expected and what happened. Include:

- your Blender version, operating system and GPU;
- the report from **Copy Diagnostics** (sidebar, N > OpenAct > Model box). It leaves out your prompts, CSV text and
  paths;
- the node's status line, if a node is involved, and a small `.blend` or CSV that shows the problem, if you can
  share one.

*Open Log* opens the model server's log, or the install log. Read a log before you attach it. The request logs that
the *Log Requests* preference writes to `<runtime>/logs/` hold your prompts and CSV text, so share them only if you
mean to.

Report security problems privately to the maintainer, not in a public issue. The model server's threat model is in
[design §16](docs/DESIGN.md#16-security--privacy).

## Set up a checkout

You need:

- Blender **4.5**, **5.0** and **5.1**, installed in their default folders
  (`C:\Program Files\Blender Foundation\Blender <version>\`), which is where the test runner looks. One version is
  enough to start: pass it with `-Versions`.
- CPython **3.11 or newer** for the pure Python suites (found as `python`, `py -3.11` or `py -3.13`).
- For the real-model tests only: an NVIDIA GPU with 10 GB of VRAM and the model runtime (see the
  [guide](docs/GUIDE.md#the-model-runtime)). Every other suite runs against a fake model server
  (`OPENACT_BACKEND=fake`), with no GPU and no runtime.

To try your changes in Blender, build the extension and install the zip from disk:

```
blender --command extension build --source-dir openact --output-dir dist
```

For quicker round trips, add a local extension repository (*Preferences > Get Extensions > Repositories > + > Add
Local Repository*) and link the `openact/` package folder into it as `openact`. Blender then loads the add-on
straight from your checkout.

## Run the tests

```
tests\run_all.ps1 [-Model] [-Versions 4.5,5.0,5.1] [-Gpu 0] [-Port 18765] [-Threads 4]
```

Every suite runs at BelowNormal priority with `OMP_NUM_THREADS`/`MKL_NUM_THREADS` set to `-Threads`,
and every Blender with `-t <Threads>`, so its `--bench` and timing figures can differ from a single
suite run at full speed.

The `*_blender.py` suites run on each `-Versions` entry. The `*_test.py` suites run under every
CPython 3.11+ found, and always inside Blender 4.5 and 5.1. `-Model` adds the e2e phases with the
real model on the given GPU, once it has 9 GB free. The port defaults to 18765 on GPU 0 and 18767
on GPU 1, and must be free: close any Blender session running OpenAct, or pass `-Port`. The runner prints a summary table and exits with 1 if anything failed.

To run a single suite:

```
blender -b --factory-startup --python tests/evaluator_blender.py
blender -b --factory-startup --python tests/startup_blender.py
blender -b --factory-startup --python tests/e2e_blender.py -- build   <file.blend> [port] [gpu]
blender -b --factory-startup --python tests/e2e_blender.py -- noaddon <file.blend>
blender -b --factory-startup --python tests/e2e_blender.py -- reopen  <file.blend>
blender -b --factory-startup --python tests/e2e_blender.py -- reopen-bumped <file.blend>
```

The e2e phases drive the add-on with the real model.

Each suite prints a `PASS` or `FAIL` line per check and ends with one `RESULT` line
([`tests/_harness.py`](tests/_harness.py)). Use the same protocol in new suites, so the runner counts them.

## Code guidelines

- **The design is the specification.** [`docs/DESIGN.md`](docs/DESIGN.md) specifies what the add-on does, and the
  code cites its sections, e.g. `(§5.4)`. When a change alters specified behaviour, update that section in the same
  pull request.
- **Keep the pure modules pure.** `csvfmt.py`, `natsort.py`, `pipeline.py`, `rules_core.py`, `store.py`, `words.py`
  and the node specs in `specs/` import no `bpy` when they load: the `*_test.py` suites run them under plain CPython.
  Import `bpy` inside the functions that need it, as the specs do.
- **Nothing runs during evaluation.** Geometry Nodes can't call Python while it evaluates. OpenAct reads words and
  asks the model outside evaluation, and writes the answers into the node's hidden group. Keep it that way: handlers
  only schedule a pass, and the model is never asked during evaluation, playback or rendering.
- **Match the surrounding code:** lines of up to 120 characters, docstrings that say what a function returns or
  why it exists, and comments that explain reasons rather than restate the code.
- **Tests come with the change.** Add or extend the suite that covers the behaviour: pure logic in a `*_test.py`,
  anything that needs Blender in a `*_blender.py`.

## Pull requests

1. Branch from `main` and keep the pull request to one change.
2. Run `tests\run_all.ps1`, on at least Blender 4.5 and 5.1, and paste its summary table into the description. Add
   `-Model` when you change the model server, the prompts or anything the e2e phases cover.
3. For a user-visible change, update [`docs/GUIDE.md`](docs/GUIDE.md) and add a line to
   [`CHANGELOG.md`](CHANGELOG.md).
4. Write commit subjects as `<type or area>: <what changed>`, in plain words, e.g.
   `fix: an unlinked ID reads the element's index without the add-on`.

## Artwork and branding

The logo, the README banner, the node cards and the roadmap are SVGs drawn by
[`tools/build_art.py`](tools/build_art.py), with their text converted to outlines. Change the data in that script
(the node cards' sockets and example values, the roadmap's items), then run:

```
uv run tools/build_art.py
```

uv installs the script's dependencies (fontTools, brotli, uharfbuzz) in a throwaway environment. The script takes
the Inter typeface (SIL Open Font License 1.1) from your Blender install, as Blender 4.5 and newer ship it; `--font`
points it elsewhere. Commit the regenerated SVGs with the script. The [branding notes](branding/README.md) say how
to use the logo.

## Maintainers: runtime lock and releases

`tools/make_locks.ps1` regenerates `openact/runtime/requirements-cu128.lock`, the runtime's hash-locked package
list, for the pinned torch and SemIf commit. It needs uv 0.8.17, the version the installer pins.

To release:

1. Bump `version` in `openact/blender_manifest.toml` and in `bl_info` (`openact/__init__.py`), and add the
   version's section to `CHANGELOG.md`.
2. Run `blender --command extension validate` and
   `blender --command extension build --source-dir openact --output-dir dist`.
3. Run every suite on 4.5, 5.0 and 5.1 with `tests\run_all.ps1 -Model`.
4. Tag the commit and create the GitHub release with `gh release create`, attaching the zip and the release notes.
